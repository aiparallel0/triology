# Audit Kit

Runnable checks for the failure families in
[01-FAILURE-CATALOG.md](01-FAILURE-CATALOG.md). Each states what it catches, how
to run it, and how to read it.

```bash
python3 docs/research-pipeline/tools/run_research_audit.py paper/asyu/main.tex
```

**Three rules this kit is built on.**

*A check that has never failed is not measuring anything.* Every tool here has a
guard that exits non-zero when the input yielded nothing to check — a file with
no claims is not a file with no problems.

*A check that cries wolf gets switched off, and then it is not a check.* Both
tools below had a false-positive pass during development and were narrowed;
those narrowings are documented, not hidden.

*Not everything can be automated.* Families A, B and G — data diligence, leakage,
scope churn — are decided in the first day and no script detects them. They are
prevented by [03-LIFECYCLE.md](03-LIFECYCLE.md), and their artifact is a written
`GROUND_TRUTH.md`, not a green check.

## 1. Claim strength — the flagship

**Catches:** a sentence stated one rung above its evidence. Family C.

```bash
python3 tools/claim_strength.py paper/asyu/main.tex [--small-n 30]
```

Four findings, each mapping to a catalogued failure:

| Finding | Catches | Failure |
|---|---|---|
| `STRONG CLAIMS WITHOUT NEARBY EVIDENCE` | rung-5 verbs with no CI, p or n in the same sentence | C6 |
| `NULL CLAIMS WITHOUT POWER` | absence of evidence read as evidence of absence | C1 |
| `SUPERLATIVES` | unfalsifiable by construction; these drift upward across revisions | C6, C7 |
| `SMALL CELLS NOT MARKED CONSISTENCY-ONLY` | an n below threshold presented as a result | C8 |

**Read it:** this tool does **not** decide whether a claim is true. It finds
sentences making a strong claim without the companion that would license one,
and hands them to a human. Automating the enumeration is possible; automating
the judgement is not.

Expect hits you will keep. An abstract compresses, and "demonstrate" in an
abstract whose body carries the intervals is fine. A sentence flagged for
`confirm there is no significant asymmetry` may be immediately followed by its
own correction — this paper's is:

> *"Strictly, McNemar non-rejection is absence of evidence for asymmetry rather
> than positive evidence of error-decorrelation."*

The checker flags the claim and the correction both. That is correct behaviour:
it surfaces the pair so you can confirm the pair exists.

**One it caught here.** The body read *"Across all three datasets and both
architectures, the combination consistently outperforms either gate alone"* —
which the paper's **own Fig. 2 caption contradicts**: on CORD, σ-alone at full
coverage is nominally higher on a larger accept set. Corrected to the comparison
that is true at matched coverage, with the exception named. This is failure C6's
exact shape, live, in a paper that had already been through four editorial
revisions and two numeric audits.

*Narrowing applied during development:* `consistency only`, `nominally` and
`too small a sample` were added to the hedge vocabulary, because the conclusion's
`(n = 15, consistency only)` — the correctly-hedged form — was being flagged as
an unqualified small cell. A checker that flags the fix is worse than no
checker.

## 2. Number provenance

**Catches:** a number that was never measured, and a number that exists twice.
Families D and the Example-3 shape.

```bash
python3 tools/number_provenance.py paper/asyu/main.tex \
    [--generated 'paper/asyu/numbers_*.tex']
```

| Finding | Catches | Failure |
|---|---|---|
| `UNBACKED result macros` | a numeric value defined in the paper with no generator | D1 |
| `TYPED WHERE A MACRO EXISTS` | a literal in the paper while its generated macro goes unused | D3, D4, D5 |
| `orphaned results` | a result computed and then dropped | Phase 5 fit |
| `no 'Auto-generated by' line` | you cannot answer "which run made this" from the file | D1 |
| `NUMERIC LITERALS in prose` | every one should be a macro, or be justified | D2 |

**Read it:** `UNBACKED` is the one that must be zero. `TYPED WHERE A MACRO
EXISTS` is the one that finds live drift risk.

**What it caught here.** Nine table cells across Tables I, II and III were typed
literals while `numbers_pooled.tex` already produced exactly those values, leaving
`\poolSigA`, `\poolIntC`, `\poolMcB` and six others unused. **This is the same
table that drifted before:** Table III's pooled row once printed b=183, c=186
where the per-corpus rows sum to 185, 188. The fix at `b9edc78` corrected the
literal — and left it a literal, so the mechanism was untouched. Nine cells now
render from the generated file.

Two residual hits are coincidental value collisions (`\ctrlLrandHi` = 0.029, and
the guard table's coverage is also 0.029). The check matches on value, so
collisions are expected; inspect, don't auto-apply.

*Narrowing applied during development:* `\newcommand` / `\renewcommand` lines
were excluded from the literal scan. They are the safe **defaults** of the
results bridge, not typed results, and flagging 85 of them buried the eleven
real findings.

## 3. Leakage table — not automatable, do it anyway

**Catches:** family B, the most dangerous family, because leakage improves every
number.

There is no script. Leakage is a property of the **checkpoint**, and no tool can
read a HuggingFace model card and know which split of your corpus it saw. Write
the table by hand, in `GROUND_TRUTH.md`, in Phase 0:

| Checkpoint | Fine-tuned on | Therefore excluded from eval |
|---|---|---|
| `naver-clova-ix/donut-base-finetuned-cord-v2` | CORD-v2 **train** | CORD-v2 train (800 of 1000) |
| `philschmid/donut-base-sroie` | SROIE | SROIE train |
| `Theivaprakasham/layoutlmv3-finetuned-wildreceipt` | WildReceipt train | WildReceipt train |

Then, in code, assert it:

```python
FINETUNED_ON = {"donut-base-finetuned-cord-v2": {"cord-v2": {"train"}}}
def assert_leakage_free(ckpt, corpus, splits):
    bad = FINETUNED_ON.get(ckpt, {}).get(corpus, set()) & set(splits)
    assert not bad, f"{ckpt} was fine-tuned on {corpus}:{sorted(bad)}"
```

**Read it:** the operational rule is behavioural, not mechanical —
**treat an unexplained improvement as a defect until explained.** That is the
only signal leakage ever gives you.

And when you do find it, fix the closure, not the file you noticed
([04-WORKED-EXAMPLES.md](04-WORKED-EXAMPLES.md) Example 1): restore → recompute
cached aggregates → regenerate figures → re-run dependent analyses → **rewrite
the prose**. The last step is the one that gets skipped.

## 4. Total-equals-parts assertions

**Catches:** D4 — an aggregate that does not equal the sum of its components.

Belongs in the **generating script**, not the paper:

```python
assert pooled["mcnemar_b"] == sum(c["mcnemar_b"] for c in per_corpus), \
    f'pooled b={pooled["mcnemar_b"]} != {sum(...)} from per-corpus'
assert 0 <= p <= 1 and isinstance(n, int) and n >= 0        # D6
assert n_after >= FLOOR, f"filter collapsed n to {n_after}"  # F5
```

**Read it:** any failure stops the run. These are the assertions Phase 1 exists
to install, and every one of them corresponds to a real commit: D4 to `b9edc78`,
D6 to `d125ba5` (figures printing `n=-217` and `n=None`), F5 to `3ef3527`
(SROIE silently collapsing 347 → 7).

## 5. Hedge drift over history

**Catches:** upward claim drift across commits, each of which looks like tidying.

```bash
git log -p --follow -- paper/asyu/main.tex \
  | grep -E '^[+-].*(hypothes|consistent with|we do not claim|underpowered|\
suggests|demonstrat|establish|prove|first|guarantee|invariant)'
```

**Read it:** manual, and worth it. A progression from *"we hypothesise"* to
*"we show"* to *"we demonstrate"* is a claim that hardened without new evidence.
The counter-example from these repos is what a *correct* drift looks like — one
commit, downward, with the analysis that forced it:

> `04ed7e2` — *"Honest grandeur fix: drop 'difficulty-invariant' overclaim
> (data-driven) … This is data-driven correction of a real overclaim, not
> reflexive softening; the law itself (reproducible 169× compression) stands."*

## 6. Sibling parity

**Catches:** family H — two papers, one gets the attention.

```bash
for t in claim_strength number_provenance; do
  for p in ../triology/paper/asyu/main.tex ../arith-gating/paper/asyu/main.tex; do
    python3 docs/research-pipeline/tools/$t.py "$p"
  done
done
```

**Read it:** compare the shape of the output, not the values. A finding present
in one paper and absent in the other is either a genuine difference or a fix
that was applied once. In these repos nearly every commit has a hand-applied
twin days later, so the second reading is the likelier one.

## 7. What this kit does not cover

Delegated to the venue-conformance playbook, which runs at Phase 5:

| Check | Where |
|---|---|
| float references — cited vs **discussed** | `paper/asyu/audit/tools/float_refs.py` |
| caption format on the rendered PDF | `paper/asyu/audit/tools/caption_format.sh` |
| placeholder leak, `\PH{}` | `paper/asyu/audit/tools/placeholder_leak.sh` |
| page count, overfull, undefined | `paper/asyu/audit/tools/gate.sh` |
| heading Title Case | `paper/asyu/audit/tools/headings_titlecase.py` |
| self-contained package | `paper/asyu/audit/tools/selfcontained.sh` |

Run both. This kit asks *is the number real, and is the sentence about it true?*
That one asks *does the rendered artifact conform?* Neither answers the other's
question, and a paper needs both answered.
